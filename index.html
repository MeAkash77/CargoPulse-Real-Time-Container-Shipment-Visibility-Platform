02 / Plain-English walkthrough

From scattered updates
to one clear answer.

Think of CargoPulse as a shared tracking desk that listens for shipment updates, remembers the latest known state, and tells people when plans change.

STEP 01
⌁

Listen for events

A port reports that a container was loaded, a vessel departs, or a terminal records a gate-in. Each update is treated as an event with a time and shipment ID.

STEP 02
⟳

Update the shipment picture

Kafka carries events between services. Spring Boot services validate updates and maintain the latest shipment state, while PostgreSQL stores durable records.

STEP 03
↗

Explain what changed

The dashboard shows the latest milestone and ETA. A delay signal can help an operations team investigate early instead of discovering a missed arrival at the last minute.

04 / Reliability by design

Make updates trustworthy.

Shipment tracking is only useful when users can trust the timeline. These are the engineering concerns this project is designed to demonstrate.

01 — CORRECTNESS

Validate every event

Check required IDs, event type, and timestamps before applying an update. Avoid moving a shipment backwards because an older event arrived late.

02 — RESILIENCE

Handle retries safely

Use idempotent event handling and controlled retries so duplicate delivery does not create duplicate milestones or corrupt shipment state.

03 — TESTABILITY

Prove expected behavior

JUnit covers backend logic and API behavior; Playwright checks the user journey, including visible status and ETA changes.

04 — OBSERVABILITY

See service health

OpenTelemetry traces requests across services; Prometheus collects metrics and Grafana can visualize latency, error rates, throughput, and consumer lag.
